# Perplexity MCP Bridge (Home Assistant Add-on)

Perplexity MCP Bridge is a Home Assistant add-on that discovers your Home Assistant entities, lets you choose exactly what to expose, and publishes a secure MCP endpoint over Cloudflare Tunnel without router port forwarding.

## Why this is safer and easier

- No public inbound router ports are required.
- Default deny model: nothing is exposed unless selected (or you intentionally choose expose-all).
- Domain-aware allowlist: actions are limited by entity type.
- Layered protection:
  - Cloudflare Tunnel HTTPS endpoint
  - dedicated subdomain
  - app bearer token
  - optional Cloudflare Access service token headers
  - per-entity and per-action policy controls
- Prevents arbitrary Home Assistant service call exposure.

## Architecture Overview

- Add-on container:
  - `FastAPI` app for local wizard + MCP endpoint
  - Home Assistant API client using Supervisor context or long-lived token fallback
  - Policy engine (entity allowlist + domain action mapping)
  - Auth middleware (bearer + optional CF Access headers)
  - `cloudflared` subprocess manager
- Public access:
  - exposed only through Cloudflare Tunnel hostname (`perplexity-mcp.example.com`)
- Internal boundaries:
  - Home Assistant admin/API is internal
  - MCP endpoint is public-facing but authenticated
  - Add-on service logic remains isolated inside container

## Add-on Setup Flow

1. Install add-on.
2. Open ingress UI.
3. Discover entities.
4. Choose exposure mode:
   - `Manually select entities` (recommended)
   - `Expose all supported entities` (explicit opt-in)
5. Configure Cloudflare:
   - paste tunnel token
   - set dedicated hostname/subdomain
6. Configure auth:
   - app bearer token (generated by default if not set)
   - optional CF Access service token headers
7. Launch secure endpoint.
8. Copy MCP URL and auth info into your Perplexity MCP connector.

## Cloudflare Requirements

Minimum required:
- A Cloudflare account.
- A pre-created Tunnel token (`cloudflared tunnel token ...`).
- A DNS hostname/subdomain mapped through the tunnel (dedicated hostname recommended).

Recommended:
- Dedicated hostname for MCP only, not your main Home Assistant domain.
- Optional Cloudflare Access policy with service token.

## Security Model (Important)

### Implemented protections

- Default deny entity exposure.
- Per-entity allowlist storage.
- Domain capability mapping:
  - `light`: on/off, brightness, color temp/color (where supported)
  - `switch`: on/off/toggle
  - `climate`: target temp / hvac mode
  - `cover`: open/close/stop
  - `sensor` and `binary_sensor`: read-only
  - `media_player`: safe basic controls
- Application auth required for MCP calls (bearer token).
- Optional CF Access header validation.
- Secret masking in logs.
- Audit logs for:
  - auth success/failure
  - tool calls
  - unauthorized attempts

### Practical limitation

There is currently no built-in cryptographic proof in this add-on that a request is "from Perplexity and only Perplexity".  
Fallback model is layered defense:
- Cloudflare Tunnel + dedicated subdomain
- optional Cloudflare Access policy
- strong random bearer token
- strict allowlist and tool constraints

## Entity Permissions

- Exposed entities are determined by:
  - exposure mode (`manual` or `all_supported`)
  - selected entities in manual mode
- Actions are validated against per-domain allowlist rules.
- Unsupported or unauthorized actions are rejected and logged.

## Revoke Access Immediately

Any of these instantly reduce/stop access:
- disable tunnel in config / stop add-on
- rotate app bearer token
- remove entity from allowlist
- revoke Cloudflare tunnel token
- tighten or revoke CF Access policy

## Development Notes

- Backend stack: Python + FastAPI for robust APIs and HTTP MCP transport.
- MCP transport: JSON-RPC style endpoint at `/mcp`.
- Local UI: static SPA served from add-on ingress.
- Persistence:
  - `/data/config.json` for policy + runtime settings
  - `/data/secrets.json` for tokens/secrets

## MCP Endpoint Basics

- Endpoint: `POST /mcp`
- Required header: `Authorization: Bearer <app_token>`
- Supported methods:
  - `initialize`
  - `tools/list`
  - `tools/call`
  - `resources/list`
  - `resources/read`

Example MCP URL to share with Perplexity:
- `https://perplexity-mcp.example.com/mcp`

## Troubleshooting

- **502 Bad Gateway / "add-on seems not be ready" i ingress**
  - Web server måste startas som **s6-tjänst** (`rootfs/etc/services.d/.../run`), inte bara `CMD /run.sh` (kan ge fel på vissa basimages).
  - Kontrollera add-on-loggar: **Inställningar → Tillägg → Perplexity MCP Bridge → Logg**.
  - `watchdog` pekar på `GET /ping` (snabb healthcheck utan Home Assistant-anrop).

- **"Failed to install add-on" / "trying to build the image"**
  - Uppdatera repot till senaste commit (korrekt `Dockerfile` + `build.yaml` med officiella `ghcr.io/home-assistant/*-base-python:3.13-alpine3.23`).
  - Öppna **Inställningar → System → Loggar** och välj **Supervisor**, eller kör `ha supervisor logs` i terminal-add-on — där står den exakta orsaken (t.ex. nätverk, fel BASE_IMAGE, eller 404 på cloudflared).
  - Om bygget misslyckas vid nedladdning av cloudflared: kontrollera att din Home Assistant har utgående HTTPS till `github.com`.

- "Cannot discover entities"
  - verify add-on has `homeassistant_api: true`
  - verify Supervisor/API connectivity
- "Tunnel failed"
  - verify tunnel token validity
  - verify Cloudflare tunnel and DNS hostname setup
- "401 on MCP"
  - verify bearer token matches configured secret
  - if CF Access enforcement is enabled, verify headers
- "Action rejected"
  - ensure entity is selected
  - ensure action is allowed for that domain

## Setup Instructions (Quick)

1. Add this repository’s **GitHub root URL** in Home Assistant (**Tilläggsbutik → Repositories**), then install **Perplexity MCP Bridge** from the store.
2. Start add-on and open ingress UI.
3. Run discovery, pick entities, and save.
4. Paste Cloudflare tunnel token and hostname.
5. Launch tunnel.
6. Use MCP URL + bearer token in Perplexity.

## Known Limitations

- Not all domain-specific edge capabilities are mapped yet.
- Cloudflare "manual mode" exists but token mode is primary.
- No direct cryptographic attestation of Perplexity origin.
